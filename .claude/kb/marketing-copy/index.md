---

## Domain Overview

Covers how to write and evaluate copy for a founder-led portfolio site — not generic marketing
theory. Every pattern here optimizes for one thing: a specific, verifiable promise that fits a
small, credible operation rather than a large agency.

| Domain | Scope | KB File |
|--------|-------|---------|
| Benefit vs. feature | Turning a feature list into a reason to care | `concepts/benefit-vs-feature.md` |
| Headline formulas | Structures for case-study and landing headlines | `concepts/headline-formulas.md` |
| Positioning statement | How to state who this is for without sounding generic | `concepts/positioning-statement.md` |
| Social proof | What counts as real proof vs. inflated claims | `concepts/social-proof.md` |
| Case study structure | Problem → Approach → Solution → Result, applied | `patterns/case-study-structure.md` |
| CTA design | Button/link copy that names the real action | `patterns/cta-design.md` |
| Landing page hierarchy | Order of promise, proof, and ask on one page | `patterns/landing-page-hierarchy.md` |
| Channel adaptation | Reusing a case's hook across LinkedIn, email, WhatsApp | `patterns/channel-adaptation.md` |

## Project Context

This KB backs a personal studio portfolio (S.H.S) built around seven shipped case studies. The
copy voice is first-person, specific, and allergic to agency jargon. Every claim traces back to
something the founder actually confirmed — this KB exists to keep that discipline as the site
grows past what one person can review from memory.
